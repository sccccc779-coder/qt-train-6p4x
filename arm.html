Module 1 · 业务底盘

云手机到底在卖什么

技术之前先立住业务。我们卖的不是「一台云手机」，客户买的也不是「一台手机」。

一句话定性
把 Android 跑在云端机房，客户远程操作一台「手机」。卖的是设备 + 环境，不是软件。
我们卖的是货源
准确说，是一套能让别人拿它去做生意的货源。硬件是入场券，真正的引擎是渠道与续费。
我们不做的事
不碰内容生产、不养号、不做代运营。只做底层的「设备与环境」，上层服务让第三方入驻（抽佣约 15%）。
市场与机房
主攻东南亚 + 北美；机房在香港，不可更换——客户问「能不能放到别的地区」时，这是硬约束，不要给承诺。

三层人，三套词（说错就是事故）

内部 / 渠道 / 板卡租赁客户
用的词
板卡、开窗数、单窗成本、返利与白标
为什么
他们按硬件与政策算账。这是唯一能谈成本结构的一层
PaaS / 白标客户
用的词
接口、能力、开窗数、单窗成本——他们自己搭 SaaS 层
注意
只讲设备层能力，不提我们自己的 C 端产品（避嫌）
SaaS 客户 / 终端用户
用的词
只讲窗口和单窗口成本，一个字不提板卡
为什么
他关心的是「一个能用的环境一个月多少钱」，不关心我们的硬件结构
口径纪律 · 同一件事三层三个说法
对内
讲成本与技术
对 PaaS / 白标
讲能力与接口
对终端用户
只讲窗口、稳定性和单窗口成本
纪律
一处说漏，后面全盘被压价
Module 2 · 行业方案

客户是谁，他拿云手机干什么

所有客户的共同点只有一句话：需要一批互不关联的干净设备 + 独立 IP。往下分五类人，打法完全不一样。

④ TSP / 代运营服务商 客单最高 · 单点裂变最强
他的现实
给客户做海外短视频 / 店铺代运营，一家背后是 100–200 个店铺（海外约 9,300+ 家）
卡在哪
要给客户提供环境，但不想自己建机房、建设备池
用云手机变成
直接买底层环境，套上自己的服务卖给客户；他只负责跟客户，环境由我们兜
打法
首攻东南亚，一个 TSP 打通就是几百个窗口
③ 批量起号工作室 算账说话 · 决策快
他的现实
靠规模出货，设备台数就是产能
卡在哪
真机的采购、充电、物流、坏机更换全是成本，还随台数线性上涨
用云手机变成
一台电脑管几百个窗口，产能与硬件解绑；加设备变成「后台多加几个窗口」
打法
给他算单窗口成本与月度总投入，数字对上他就下单
⑤ 工具用户（已买指纹浏览器 / 代理 IP）
他的现实
已经有账号环境方案，认知成熟，不用教育
卡在哪
手里有 IP、有浏览器指纹，缺「设备」这一层
用云手机变成
设备层补齐，IP 与设备一个后台一张账单，不用在两个供应商之间对账
打法
转化最快的一类，讲清「我们是底层设备，不抢你的客户」即可
② 社媒矩阵运营（TikTok / IG）
他的现实
几十到几百个账号做矩阵，靠内容与规模吃饭
卡在哪
起号成本高、批量操作累、人工切号容易出错
用云手机变成
一个窗口一个账号，批量创建 + 自动化任务 + 同步器，复购稳定
打法
试错意愿强，先小批量试，跑通再放量
① 跨境多店铺卖家
他的现实
一个卖家开 N 个店，店铺就是资产
卡在哪
账号关联被封、店铺全灭——他最怕的是一夜清零
用云手机变成
一店一窗口一 IP，设备层彻底隔离，关联风险显著下降
打法
决策慢、怕踩坑，需要先被教育，周期最长——别把开单指望压在他身上
先打谁：优先级 ④ > ③ > ⑤ > ② > ①
TSP / 工作室
算得过账就买，最先打
工具用户
现成客户，最省教育成本
社媒矩阵
要批量与自动化
跨境卖家 ①
要先被教育，周期最长

落地场景：客户真正在跑的事

跨境电商多店铺
一个卖家管一批店，怕的就是关联。核心诉求是设备隔离 + 独立 IP + 店铺长期存活。
社媒矩阵运营
TikTok / IG 等平台的账号矩阵，几十到几百个号。核心诉求是批量操作与自动化，不是单台性能。
应用测试
需要一批干净、可重置、机型可配的 Android 环境做兼容与回归测试。核心诉求是可批量重置。
设备托管
把设备放在云端集中管理，团队成员按权限分工操作。核心诉求是权限与一个后台。
场景库怎么用
存量
约 50 条，白帽与灰产分开存放
涉灰部分
只在合规培训里单独讲
对外
一律只描述技术能力

合规红线：这四类客户一律不接

不管单多大，遇到就上报，不自己判断「应该没事」
① 无流量
大额采购，却拿不出对应的业务流量
② 要藏量
要求隐藏流量 / 魔改空转
③ 款异常
付款来源异常（第三方代付、来路不明）
④ 要回扣
谈条件时直接索要回扣
定性
涉嫌帮助信息网络犯罪活动罪（帮信罪）
后果
单位 + 个人双罚——不是罚公司就完事
动作
不接、不议价，留证据，直接上报主管

能说 / 不能说（说错一句就是虚假承诺）

绝对不能说
承诺类
保证不封号 / 包过风控 / 绝对安全 / 查不到
越线类
帮你养号 / 批量注册账号 / 规避实名 / 代过人脸

能力类
设备环境隔离、独立 IP（只描述技术能力）
效果类

场景类

我们卖的东西，强在哪

这一节是内部清单：客户认什么、我们有什么、对应哪句话。只讲我们的优势，不做任何参数对照。

产品规格：按开窗密度分四档

档位窗 / 卡内存 / 窗存储 / 窗三项认证定位
入门档6 窗2.7 GB30 GB—引流
主力档4 窗4 GB45 GB—走量

一卡多窗 → 窗口越多、单窗成本越低，但每窗分到的内存越薄、体验下降。这是云手机最核心的取舍变量。

客户认的六个能力点

① 真实 ARM 环境，不是模拟层
客户得到什么
应用原生跑，加固包装得上、跑得稳；设备特征与真机同源
怎么说

② 每个实例独立设备指纹
客户得到什么
账号之间在设备层面互不关联——这是卖家最怕的那件事的反面
怎么说
「一台设备一个身份。指纹真不真，客户测不出来，最后看的是账号存活率。」
③ 独立代理 IP，可单独买也可打包
客户得到什么
设备 + IP 一个后台、一张账单，不用在两个供应商之间对账
怎么说
「有设备没干净 IP，账号照样关联；我们对这两层一起负责。」
④ 批量操作与自动化
客户得到什么
批量创建、任务下发、同步器——一台机上的操作同步到一批窗口
怎么说
「同一批人，从管二十台真机变成管两百个窗口。」
⑤ 三项安全认证（海外硬门槛）
客户得到什么
Google Play 认证 / SafetyNet / Widevine L1 齐全——很多海外场景没有这三项直接出局
怎么说
「应用商店、谷歌服务、高清播放这些要求真机特征的地方，我们过的就是这三关。」
⑥ 一卡 3–6 窗，窗数可变
客户得到什么
同样一张卡，按他的业务密度配窗口数，单窗成本更可控
怎么说
「同行产品线通常写死。窗数越灵活，你的单窗成本越低——我拿你现在的量算给你看。」

Module 4 · 背景

ARM 只记三件事

芯片层的东西不用背——客户不会跟你聊晶圆和 IP 授权。你只要记住这三句，然后立刻接到云手机上。

① 解释 ARM
手机芯片用的架构就叫 ARM。Android 应用天生就是为 ARM 编译的——这一句能解释掉我们 80% 的技术选择。
② 一句话说行业
云行业的硬件底座正在往 ARM 转（AWS、Google、阿里都有自己的 ARM 芯片），我们采购的板卡就在这条供应链上——它的价格、供货节奏、代际更新都会传导到我们的成本。
③ 说我们自己
我们买真实的 ARM 板卡，一张卡切成多个窗口，一个窗口 = 一台独立云手机。同一张卡窗数可变（3 到 6 个），是同行通常做不到的灵活性。

客户会问的三个 ARM 问题

「ARM 到底是什么？」
一句话答
手机和 Android 设备用的芯片架构。我们跑的是真实的 ARM 硬件，不是套一层模拟。
别展开
客户不是来听架构课的，答完立刻转到「所以你的应用装得上、跑得稳」。
「ARM 是不是不如别家的芯片？」
一句话答
「这项我们确实不比参数——我们不比谁的核多，比谁能让你赚得多。」
为什么这么说
云手机的战场不在芯片参数，在「环境真不真、能不能规模化、单窗口多少钱」。参数仗不是我们的战场（详见第 12 模块竞品）。
「我看报道说 ARM 已经占服务器市场 50%」
一句话答
「这个数字看口径——同一件事有三种说法：15%（数据中心 CPU 份额）、25%（服务器 CPU 市场）、50%（厂商目标）。」
关键动作
引用任何份额数字，必须同时说出口径和时点。说不清就承认「我只记得方向，具体比例要回去查」——比编一个数字安全得多。
为什么这么点就够
前提
这门课讲云手机，不是讲芯片
作用①
解释我们为什么必须是这个架构（第 5 模块）
作用②
知道板卡从哪来、成本受什么影响（第 7 模块）
其余细节
客户不会问，问了也能回去查
Module 5 · 核心

云手机为什么必须是 ARM

全课最重要的一节。客户问「为什么非要用 ARM」「能不能再便宜点」时，答案在这里。

标准答案（背下来）
原理
Android 应用原生编译为 ARM 指令
我们
真机 ARM 原生执行，设备特征与真机同源
所以过得去
兼容性、播放认证、平台信任校验
反面
非 ARM 环境要多一层转译：性能与兼容性都打折

为什么「原生 ARM 环境」值钱

把技术讲成客户能感受到的三件事，比背参数有用。

原生执行：应用不用「翻译」
技术事实
Android 应用原生编译为 ARM 指令，在真实 ARM 芯片上直接执行，中间没有翻译层
客户感受
加固应用装得上、跑得稳；不用为「能不能跑」反复试错
设备特征与真机同源
技术事实
每个实例有独立设备指纹，硬件特征来自真实 ARM 服务器
客户感受
平台信任校验过得去，账号存活率是客户最在意的一件事
能规模化
技术事实
一台物理卡切出多个窗口，配合批量创建与自动化任务下发
客户感受
同一批人从管二十台真机，变成管两百个窗口
客户提别的方案时怎么答
只说
技术路线的差异
不说
不指名厂商、不做硬件参数对照
落点三问
要几个环境、跑多久、单环境每月能接受多少钱

「三重认证」为什么能当卖点

Play 认证
设备通过 Google 兼容性认证（GMS），应用商店、支付、谷歌账号登录这些场景才能正常用。
SafetyNet
平台判断「这是不是真机」的完整性校验（SafetyNet / Play Integrity）。转译层、改机环境常常过不了。
Widevine L1
流媒体最高等级的内容保护。Netflix 等要放高清就要求 L1，而 L1 依赖真实的硬件信任链。
为什么这三件事绑在 ARM 上
同一件事
它们验证的都是「设备特征是不是真的」
过得去
跑在真机 ARM 上、每实例独立指纹
过不去
转译或改机环境里补，越补越破绽

Module 7

开窗密度：云手机最核心的一道算术

通用云按「台 / 核」卖，云手机按「窗口」卖。这一个字的差别，决定了整门生意的算法。

三个词，三张嘴

板卡 内部词
硬件成本单位。只在内部成本核算、PaaS / 白标技术对接、渠道拿货这几个场合出现。对 SaaS 客户和终端用户一个字都不提。
窗口
用户层的计价单位：一个窗口 = 一台能用的云手机（独立系统环境、独立 IP、互不干扰）。
开窗密度
一张物理卡切出多少窗口。切得越多，单窗口成本越低，但每窗口分到的内存与存储越薄。

板卡上装的是什么芯片（我们的供应链）

瑞芯微 RK3588
规格
8nm，4×A76 + 4×A55，Mali-G610 GPU
算力
6 TOPS NPU，8K 解码
内存
LPDDR4X 4–32GB，eMMC 存储
角色
走量款主力；实测 8 个实例可用、大型游戏吃力
此芯 P1（CD8180）
规格
6nm，12 核 Armv9，Immortalis-G720 GPU
算力
NPU 30 TOPS，综合 45 TOPS，8K 编解码
内存
LPDDR5 128-bit，最大 64GB 共享内存
角色
新一代旗舰：高配档板卡，多开余量足
板卡选型看四件事
内存带宽
决定能切几窗，第一条约束
编解码
短视频 / 直播类客户会直接问
认证
Play / SafetyNet / Widevine 能不能过
供货
代际与供货周期，直接影响成本与交付

芯片规格以厂商官网为准。客户问「你们用什么板卡」时按对接口径回答，不展开内部成本与开窗参数。

密度与体验是跷跷板
规律
密度越高，单窗成本越低，体验越差
别承诺
「越多越划算」
先问清
跑几个应用、要不要相机、是否长期挂机

这道算术怎么影响报价

对内部：算成本
怎么算
硬件成本天然按卡算 → 倒推单窗口成本 = 单卡成本 ÷ 开窗数 + 带宽 + IP

竞品格局：不比参数，比模式

三类对手，一条铁律：不比内存、不比核数。硬件参数我们不占优，比参数是自曝短板。

竞品甲 · 虚拟机系（同集团另有 IP 品牌 + PaaS）
客户会怎么问你
「XX 家内存是你们两倍」——这是他们最强的一张牌
他的软肋
严格管控代理零售价，违规没收激活码（第 1 次扣 10%、第 2 次扣 20%）；下级违规上级连坐封码；代理单台毛利极薄；白标要走商务，不透明
我们的接法
承认参数差距 → 把战场换到政策：不控价、不没收码、不连坐、白标自助
竞品乙 · 联盟返佣型
客户会怎么问你
「他家返佣给得比你们高」
他的软肋
无代理体系；设备费 + 启动费双重收费，结构复杂；年付折扣绕来绕去
我们的接法
讲结构不讲数字：我们是可持续收钱的客户关系，不是一次性差价；政策条款签协议前全透明
竞品丙 · IP 供应商
客户会怎么问你
「IP 我直接找 XX 买就行」
他的软肋
只做 IP 一层，做不了设备层——客户还得再找一家设备供应商，两套账两个客服
我们的接法
设备 + IP 一个后台一张账单；IP 可单独买、也可随设备打包，打包更划算

对手在干什么（可直接引用，只说事实）

价格管控

下级代理违规 → 上级连坐封码。代理既要管自己，还要替下级兜风险

白标要走商务审批，条款不透明，小代理拿不到

各家公开比例口径不一，部分厂商招募页写得很虚——一个具体数字都没公布

① 代理自由定价

Appendix

术语速查

客户提到这些词时不要慌，含义都在这里。

指令集架构
CPU 认识的语言规范。不同架构是并行的体系，机器码互不通用，程序必须针对目标架构编译。
Neoverse
ARM 面向服务器的 IP 核系列，分 V／N／E 三条线；云厂商自研芯片多基于它。
Cortex
ARM 面向手机、嵌入式等终端的 IP 核系列。你手机里的核心多半是它。
二进制转译
把一种架构的机器码翻译给另一种执行，性能与兼容性都有损耗；客户说的「模拟器方案」就是它。
窗口
用户层的计价单位：一个窗口 = 一台独立云手机（独立系统环境、独立 IP）。对外报价、客户算账都用它。
板卡
内部词，硬件成本单位。只在内部核算、PaaS / 白标技术对接、渠道拿货时用，对客户不提。
开窗密度
一张物理卡切出多少窗口。密度越高单窗口成本越低，但每窗口内存与存储被摊薄——密度与体验是跷跷板。
设备指纹
设备软硬件特征的集合（机型、IMEI、MAC、系统参数等）。云手机为每个实例生成独立指纹，用于隔离账号环境。
三重认证
Play 认证 / SafetyNet / Widevine L1，三者都要求设备特征真实。
单窗口成本
客户视角的核心指标：每个窗口每月多少钱。客户真正会比较的是它，不是整机或整卡价格。
TCO
总拥有成本，含采购、能耗、运维、人力。只比单价容易得出错误结论。
环境隔离
账号跑在独立的设备与网络里，平台看不出关联——指纹 + 独立 IP + 行为，三样齐了才叫隔离。
账号关联
平台判断「这几个账号是同一个人」：指纹相同、IP 相同或异常、行为雷同。跨境卖家最怕它。
指纹浏览器
伪造浏览器指纹做多账号的工具。它只解决网页层，缺的正是设备层——这类用户最现成。
代理 IP 的类型
住宅 IP（最干净也最贵）/ 机房 IP（便宜、易识别）/ 移动 IP（稀缺）——客户问「干净吗」就是问这个。
群控与同步器
群控 = 批量控制多台；同步器 = 一台操作实时同步到一批窗口。
自动化任务
按脚本批量执行操作（登录、发布、点击等）。客户说「能不能让它自己跑」，指的就是这个。
TSP
海外短视频电商服务商，一家背后常带 100–200 个店铺——我们客单最高、裂变最强的一类。
白标
客户用自己的品牌对外销售我们的底层能力。透明自助白标（注册即解锁基础版）是我们相对同行的差异点之一。
留存与复购
客户每月续费才是收入主体。客户流失 = 渠道的持续收入断掉——所以所有动作最终都指向「让客户用下去」。
