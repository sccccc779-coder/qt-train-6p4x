第 1 课

三层回顾：IaaS、PaaS、SaaS

这三个词是云计算行业的地基。用租房打比方，一句话就能分清。

房子还是那套房子，区别在于「你管多少事」

IaaS
租毛坯房

房东给你墙、地、水电。装修、家具、打扫，全是你自己的事。

一句话：卖的是「资源」——服务器、网络、存储。

PaaS
租精装公寓

水电、家电、网络都弄好了，你拎包入住。

一句话：卖的是「能力」，调接口就能用。

SaaS
住酒店

什么都不用管，付钱就住。但你也不能改房间结构。

一句话：卖的是「成品」，打开就能用。这是我们的客户在做的事。

放到云手机这门生意里，长这样

IaaS · 基础设施
提供什么
机房里的服务器、网络、存储
行业里对应
租 ARM 服务器、拉带宽、拿公网 IP
谁在做
云厂商、机房
PaaS · 平台能力
提供什么
把资源变成能调用的「能力」
行业里对应
调一次接口就开出一台云手机，能批量管、能看画面
谁在做
我们
SaaS · 现成软件
提供什么
打开就能用的成品
行业里对应
多店铺管理工具 / 多账号运营网站
谁在做
我们的客户
一句话记住IaaS 卖「资源」，PaaS 卖「能力」，SaaS 卖「成品」。
越往上，客户要自己做的事越少，但能改的东西也越少。
为什么这一课要放在最前面因为「我们站在哪一层」直接决定了「谁是我们的客户、客户拿我们做什么、跟他们该用哪套词」。
这一层站错了，后面所有的沟通都会歪。
第 2 课

我们是 PaaS，客户是 SaaS

同一个平台，链条上不同位置的人看到的东西完全不一样。点开下图任一角色，看它在业务里的实际含义。

⚠ 一条铁律：做 PaaS / 白标，别碰客户的地盘
我们自己有 C 端 SaaS 产品，就叫 QT Phone——面向终端用户的云手机。这一点内部必须清楚，别对外说错。
但对 PaaS 客户、白标客户，不要透露我们有 C 端产品——一旦说出去，客户会立刻认为你在跟他抢终端市场，接着就是防你、压价、找备胎。
对客户只说能力层：「我们只做下面这层能力，上面的产品是你们的，我们不碰终端。」
点击图中任一角色了解它在业务里的实际含义。

同一件事，三层人看到的东西完全不同

我们（PaaS）
他买的是什么
可调用的能力：开窗口、装应用、批量管、接口对接
他嘴里的话
「能不能批量开窗口？能不能拿到设备信息？任务跑完没？」
他真正在意的
资源利用率、稳定性、能不能支撑客户的量
我们的客户（SaaS）
他买的是什么
我们的能力 + 他自己的软件
他嘴里的话
「窗口稳不稳？能不能对接？出问题谁负责？」
他真正在意的
窗口稳不稳、能不能对接、出问题谁负责
终端用户
他买的是什么
打开就能用的服务
他嘴里的话
「好用吗？贵不贵？会不会出问题？」
他真正在意的
体验和结果，完全不知道背后是云手机
一句话定性我们卖的不是「一台云手机」，而是一套能让别人拿它去做生意的能力。
所以客户提的往往是「批量、稳定、可控、能对接」，而不是「界面好不好看」。
别忘了还有第三种客户除了「自己做 SaaS 卖给终端」的客户，还有把云手机能力嵌进自己工具的客户，以及渠道贴牌 / 做板卡租赁的伙伴。
前两类是 SaaS 视角，第三类是渠道视角——两边用的词不一样，第 3 课专门讲这件事。
第 3 课 · 本课重点

★ 核心口径：用户层只按「窗口」算钱

这一课只要记住一句话：面对 SaaS 客户和终端用户，我们的计价单位是窗口，不是板卡。

先弄懂：什么叫一个「窗口」

硬件底座上可以切出多个窗口，一个窗口 = 一台独立云手机：有自己的系统环境、自己的 IP，互相不干扰。

同一张硬件卡，能切出多少个窗口是可调的——这是这套业务里灵活性的来源。但有个取舍必须记住：

开窗密度的取舍切得越多，摊到每个窗口的成本越低，但每个窗口分到的内存和存储被摊薄，体验会下降。
所以不要对客户承诺「越多越划算」——密度和体验是同一根跷跷板的两头。

用户层看到的世界，只有三件事

开窗口

开通一个窗口，就得到一台能用的云手机。

按窗口计费

用了几个窗口、用了多久，就是账单的全部依据。

算单窗口成本

客户要比较的是单个窗口的成本，不是整机、整卡的价格。

★「板卡」只出现在三个地方

板卡是我们的硬件成本单位，属于视角内部的词。它只在这三种场合出现：

① 内部成本核算机密，不外传
谁在用这个词
我们自己
为什么这里必须用它
硬件成本天然按卡算，才能倒推出单窗口成本
② PaaS 客户
谁在用这个词
自己搭 SaaS 层、要 API 接入的客户
为什么这里必须用它
他们买的是底层能力，关心开窗密度和接口，是技术采购视角
③ 渠道贴牌 / 板卡租赁
谁在用这个词
渠道伙伴
为什么这里必须用它
他要按「一张卡能开几窗」算自己的成本，这是他赚钱的算法
点击任一视角看清它在实际沟通里对应谁。
对 SaaS 客户说「板卡」，就是错层 SaaS 客户和终端用户的世界里没有板卡这个概念。他们只知道「我开了多少个窗口、每个窗口多少钱」。
你一开口说板卡，客户会立刻察觉你在用另一套计价单位思考——后面所有关于价格、成本、容量的对话都会歪掉。
一句话纪律：对内部和渠道说板卡，对用户层只说窗口和单窗口成本。
两个常见的搞混 · 客户说「我要 50 台」——在用户层，一台就是一个窗口，说窗口不会错。
· 技术同事嘴里可能听到「实例」「镜像」等词，那是对接层面的叫法，指的是同一个东西的不同侧面；但面对客户，计价单位只有一个：窗口。

术语速查表

开会时听到不懂的词，回来查这里。

窗口
用户层的计价单位。一个窗口 = 一台独立可用的云手机（独立系统环境 + 独立 IP）。客户说的「一台」就是它。
单窗口成本
把费用折算到一个窗口上看是多少。整机、整卡都不属于这个视角。用户层只认这一个单位。
开窗密度
同一份底层资源切成多少窗口。密度越高单窗成本越低，但每窗内存与存储越薄——核心取舍。
板卡
硬件成本单位，只出现在三处：内部成本核算、PaaS 客户、渠道贴牌与板卡租赁。
实例
技术对接层面的叫法，指一台云手机。跟客户谈计价时，统一说「窗口」。
镜像
预装好系统和应用的模板。用同一个镜像开出来的窗口初始状态一致，是批量部署的基础。
IaaS
基础设施即服务，卖「资源」（服务器、网络、存储）。相当于租毛坯房。
PaaS
平台即服务，卖「能力」，客户通过接口调用。我们在这个位置，相当于租精装公寓。
SaaS
软件即服务，卖开箱即用的成品，最终用户直接用。我们的客户在这一层，相当于住酒店。
IP
公网地址。客户在意的不只是「有多少个」，而是干不干净、能不能跟着窗口一起配好。
环境隔离
每个窗口是独立的环境，互相不影响。这是「一窗口一账号」类业务能成立的基础。
账号关联
目标平台把多个账号判定为同一批人在操作。设备环境与 IP 是降低关联风险的其中两层，但不是全部。
渠道贴牌
渠道伙伴用自己的品牌对外销售。这一层的核算视角和用户层不同，会用到板卡与开窗密度。
三项认证
Google Play / SafetyNet / Widevine L1 等应用与安全认证，海外业务的实际门槛，部分高要求场景会指定。
